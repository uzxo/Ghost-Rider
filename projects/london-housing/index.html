An ensemble for London property prices.

Stacked tree-based and linear models trained on a rich set of property and neighbourhood features. Geospatial EDA, SHAP-based explainability, and a residual analysis that traces error back to specific feature regimes — not just a single MAE number on a slide.

What it is

Overview

A regression problem that on the surface looks simple — predict the price of a London property from its features — and that in practice rewards every ounce of care you put into the data. The interesting bits are not the headline R²; they are what the residuals reveal.

The pipeline starts with extensive EDA, including a geospatial pass that maps prices and residuals onto London boroughs to surface neighbourhood-level patterns. Features are engineered carefully (one-hot for categoricals, log-transforms where the distribution demands it, target-encoded postcodes), then fed into a stack: gradient-boosted trees as the base learners, a regularised linear model as the meta-learner.

Explainability uses SHAP — both global feature importances and per-prediction attributions — so the final model is not a black box but a structured decomposition of "where does this price come from?" The error analysis then reverse-engineers the residuals: which property types break the model? Which neighbourhoods? Which price brackets?

The deliverable is a notebook that walks through every step, a written report, and the cleaned dataset.

What's inside

Pipeline
№ 01

Geospatial EDA

Prices and residuals mapped onto London boroughs. Clear visual evidence of where the model agrees with the market — and where it does not.

№ 02

Feature engineering

One-hot for categoricals, log transforms for skewed distributions, target encoding for high-cardinality postcodes, and engineered interactions.

№ 03

Stacked ensemble

Gradient-boosted trees (XGBoost / LightGBM) as base learners, regularised linear regression as the meta-learner. Cross-validated all the way down.

№ 04

SHAP explainability

Global feature importances and per-prediction attributions — the model is auditable, not a black box.

№ 05

Error analysis

Residuals broken down by property type, location, and price bracket. The model's failure modes are documented, not hidden behind an aggregate MAE.

№ 06

Honest reporting

Cross-validated metrics with variance, plus a held-out test set that is touched exactly once at the end.
